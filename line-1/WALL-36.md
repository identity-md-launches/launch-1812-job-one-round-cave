# The Fitting Seed

The new piece, `tools/snapshot-request-match/`, checks a saved Ethereum RPC
snapshot against the public-read method and parameters a worker explicitly
intended. It reuses the bounded snapshot validator and safe workspace file
reader unchanged. Its README gives an offline command using the real saved ZTO
totalSupply observation. All 17 focused tests passed; the matching example exits
0, and changing the expected block tag to `finalized` exits 1 with `/params/1`.
An independent agent repeated those checks and found no blocking issue.

This adds request-intent comparison, not authentication of the response or a
chain proof. The historical ZTO observation has a moving `latest` tag and no
recorded block anchor. No fresh chain observation or transaction was made.

The wall began with record 35's SHA-256-verified PNG. The built-in imagegen tool
painted a red-ochre seed in a matching charcoal hollow below Pepe. Its generated
background was discarded: FFmpeg transferred only the new dark pigment onto
the original unpainted stone, with darken-only blending. The exact prompt is in
`wall-prompt-36.txt`; `finish_wall_36.py` records the one-time formatting process.
That script requires the two original input hashes and deliberately refuses a
second application to the finished wall. FFmpeg was already installed; the
delivered snapshot tool itself uses only Python's standard library.

Only 2,213 pixels changed, within x 597–652 and y 855–939; the other 1,570,303
pixels are exactly ancestral. The central Pepe, both five-digit hands, all older
marks, rock outside the new pigment, cracks, lighting, water and framing remain.
No letters, numbers, captions, logos, frames or additional hands were observed.
The final PNG and decoded JPEG were visually inspected. No unmet visual
requirement was identified by this local review.

The complete wall is a 1254 × 1254 RGB PNG at both
`artifacts/line-1/wall.png` and the named output
`artifacts/line-1/wall-v16.png`. Record 36 is `dist/line-1/36.json`, with the
required 512 × 512 JPEG beside it at `dist/line-1/36.jpg` (71,852 bytes).
`wall-review-36.json` records formats, hashes and preservation counts;
`check-results-36.json` retains the actual tool checks and delivery checks.
GOAL.md and every older numbered record and thumbnail are unchanged.

All checks here are local observations, not independent certification. The image
generation draft is not a deliverable; only the completed wall and its required
thumbnail are retained in the workspace.
